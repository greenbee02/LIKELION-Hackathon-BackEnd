# 리워드·이벤트 운영 정책

## 확정 정책

- 달성률에는 `ACTIVE` 상태 카드만 반영한다.
- 공식 컬렉션의 `is_required = TRUE` 상품만 달성률에 포함한다.
- 같은 `product_id` 카드가 여러 장이어도 한 번만 인정한다.
- 리워드와 이벤트는 사용자당 같은 대상에 대해 한 번만 해금한다.
- 이벤트 해금은 참석 확정이 아니라 **우선 신청 자격**이다.
- 이벤트는 수령 처리 대상이 아니며, `events.end_at`이 지나면 만료 대상으로 본다.
- 일반 리워드는 `rewards.expires_at`이 있는 경우에만 만료 대상으로 본다.

## MVP 수령 처리

- 현재 스키마에는 매장 직원 계정·권한·수령 직원 이력이 없다.
- 따라서 고객 API는 `claim_code`를 발급·조회하는 단계까지만 제공한다.
- 실제 매장 직원의 코드 확인 뒤 `CLAIMED`로 바꾸는 API는 직원 도메인 추가 후 구현한다.

## API 범위

- `GET /api/v1/rewards/progress`: 공식 컬렉션별 달성률과 해금 조건
- `GET /api/v1/rewards/my`: 내 리워드·이벤트 자격과 상태
- `POST /api/v1/rewards/{userRewardId}/claim`: 일반 리워드 수령 코드 발급

## 이후 DB 보강

- 동시 해금 중복을 DB에서도 막기 위해 PostgreSQL 부분 유니크 인덱스를 새 Flyway 버전에 추가한다.
- 매장 수령 구현 시 직원 식별자와 수령 매장·처리 시각 이력을 별도 저장한다.
